# 面向磁盘驻留图近似最近邻搜索的空间局部性感知缓存

## 1. 重新理解观测到的局部性

当前的 SIFT1M 实验表明，将测试 query 按 k-means 聚类排序后，动态节点缓存能够获得显著更高的命中率。在缓存容量为 10,000 时，LRU 的命中率从原始顺序下的 9.21% 提升到 k-means 顺序下的 37.09%。Belady 离线最优策略给出的上界则从 24.70% 提升到 47.12%。

仅将这种现象称为时间局部性并不完整。重用确实发生在时间维度上，但其根源是几何关系：

- 向量空间中距离相近的 query 往往会进入相似的图区域；
- 它们的图遍历过程会扩展相互重叠的全精度节点；
- 将相近的 query 相邻排列，会缩短这些节点的重用距离；
- 传统的时间局部性缓存随后间接捕捉到这种重用。

因此，有意义的负载变量不仅是节点访问序列 `v_1, v_2, ...`，还包括联合过程 `(q_t, E(q_t))`，其中 `q_t` 是 query 向量，`E(q_t)` 是该 query 扩展的图节点集合或有序序列。

对于查询区域标签 `z`，定义节点亲和度：

```text
A[v, z] = P(v is expanded | query belongs to region z).
```

与空间局部性对齐的缓存应当根据 `z` 和 `A[v,z]` 预测未来重用，而不能只依赖 `v` 的最近访问时间或全局访问频率。

## 2. 为什么为每个聚类物理拆分独立缓存并不是完整设计

所提出的按聚类分区缓存是一个有力的基线，因为它容易解释，并且可以直接检验这一假设。然而，它仍然存在若干结构性问题。

### 2.1 节点重复

入口区域节点、靠近 medoid 的节点、枢纽节点以及桥接节点可能对多个 query 聚类都有用。将这些节点物理复制到多个聚类缓存中会浪费容量。当缓存条目同时包含全精度向量和邻接表时，这一问题尤其严重。

### 2.2 硬路由错误

位于聚类边界附近的 query 可能会遍历与两个或更多区域相关的节点。将 query 硬分配给单个聚类，会把所有准入操作都发送到同一个缓存，并可能从错误的分区中淘汰有用节点。

### 2.3 容量需求并不只取决于聚类规模

一个聚类中的历史 query 数量可以估计其到达概率，但不能直接反映该聚类所需的缓存容量。两个同样热门的聚类可能具有不同的图工作集大小、路径重叠程度、路径长度和节点共享率。

### 2.4 固定聚类会过时

生产环境中的 query 分布会发生漂移。固定的离线分区可能使容量滞留在不活跃的聚类中，同时新的聚类却不断发生缓存抖动。

### 2.5 物理 I/O 单元可能是页面

DiskANN 在逻辑上缓存节点，但 SSD 读取和图布局是面向页面或扇区的。如果一个查询区域中的有用节点分散在多个页面上，那么节点层面最优的分区未必能最小化页面读取次数。

基于这些原因，物理上相互独立的聚类缓存应当作为实验基线实现，而不应作为最终架构。

## 3. 推荐设计：Query-Affinity Shared Cache

推荐设计采用单一的、去重的物理缓存，并根据 query 条件执行准入、淘汰和逻辑容量计费。本文将其称为 Query-Affinity Shared Cache，简称 QASC。

### 3.1 组件

1. **查询路由器**

   维护 `K` 个 query 原型。对于每个 query，返回一个硬聚类 id，或者一个软 top-`m` 分布 `p(z | q)`。对于靠近边界的 query，优先采用软路由。

2. **节点亲和度统计**

   维护指数衰减计数：

   ```text
   expansion_count[v, z]
   hit_count[v, z]
   last_access_epoch[v, z]
   ```

   与稠密的 `num_nodes x K` 矩阵相比，更适合为每个节点维护一个压缩后的 top 聚类列表。

3. **单一物理节点存储**

   每个图节点至多存储一次。一个已缓存节点可以服务于所有 query 聚类。聚类归属是元数据，而不是重复的数据载荷。

4. **全局和条件逻辑层**

   将一部分容量预留给可在全局范围重用的节点，其余容量分配给聚类特定节点。这两个层可以是同一个数据载荷存储之上的两组策略列表，而不是两份数据副本。

5. **配额控制器**

   逻辑聚类配额约束哪个聚类可以触发淘汰，但未使用的容量可以被借用。配额根据实测的边际命中收益定期更新。

### 3.2 全局节点与聚类特定节点

对于节点 `v`，对其跨聚类的亲和度分布进行归一化：

```text
p(z | v) = expansion_count[v,z] / sum_j expansion_count[v,j].
```

利用该分布的熵区分节点角色：

```text
H(v) = -sum_z p(z|v) log p(z|v).
```

- 高支持度且高熵：全局/共享节点；
- 高支持度且低熵：聚类特定节点；
- 低支持度：较弱的准入候选；
- 较高的早期跳数访问频率：可能是导航骨干节点。

这直接解决了入口区域节点重复的问题：这些节点只在全局共享层中存储一次。聚类缓存仅保留剩余的区域特定工作集。

### 3.3 准入评分

一个实用的初始评分函数是：

```text
utility(v, q) =
    io_cost(v) / entry_size(v)
    * sum_z p(z | q) * reuse_probability(v, z)
    * confidence(q)
    - admission_penalty(v).
```

`reuse_probability(v,z)` 最初可以使用指数衰减的扩展频率表示。后续版本可以预测重用距离，或者预测一个时间窗口内的期望命中次数。

准入评分应当与当前受害者条目的效用进行比较。这可以避免将每一个被扩展的节点都写入聚类配额，从而污染缓存。

### 3.4 淘汰与逻辑成本分摊

当一个节点对多个聚类都有用时，只存储一次会带来计费问题。可以按比例分摊其逻辑大小：

```text
charge(v,z) = size(v) * demand(v,z) / sum_j demand(v,j).
```

物理占用仍然只有一个条目。逻辑计费使每个聚类都可以消耗自身配额，而不需要创建副本。淘汰过程在满足各聚类最低服务水平的前提下，选择全局边际效用较低的节点。

### 3.5 容量分配

不要只使用 `C_z proportional to number_of_queries_z`。它可以作为有用的基线，但首选目标应当是边际命中收益。

通过 trace replay 为每个聚类测量命中曲线 `H_z(c)`。将下一个缓存单位分配给以下值最大的聚类：

```text
arrival_rate_z * (H_z(c + delta) - H_z(c)) / delta.
```

这相当于在经验未命中率曲线上进行注水式容量分配。它会自动为具有较大可重用工作集的聚类分配更多容量，同时避免给命中曲线较早饱和的聚类分配过多容量。

可采用的基线包括：

```text
C_z proportional to n_z
C_z proportional to sqrt(n_z)
C_z proportional to n_z^alpha, alpha in {0.5, 0.75, 1.0}
C_z proportional to arrival_rate_z * unique_working_set_z
```

一个稳健的实现还应包含：

- 为每个活跃聚类设置最小配额；
- 设置一个共享弹性池，初始占总容量的 20-40%；
- 当其他聚类空闲时允许借用容量；
- 引入滞后机制，避免配额在每个 epoch 都发生振荡。

## 4. query 原型应当从哪里获得

推荐的数据源优先级如下：

1. **保留到达顺序的历史生产 query。**

   这是唯一能够直接捕捉需求和序列行为的数据源。

2. **具有代表性的离线学习 query 集。**

   如果已经验证其分布与线上 query 一致，则适合用于冷启动。

3. **检索模型的训练 query。**

   这些 query 可以用于初始化语义区域，但训练阶段的采样方式可能有意与服务流量不同。

4. **将基向量或采样图节点作为伪 query。**

   这种方法估计的是语料库几何结构，而不是实际需求，因此只应作为冷启动时的后备方案。

推荐采用混合生命周期：

- 使用离线学习 query 或基向量样本初始化原型；
- 收集一个有界的在线 query 窗口；
- 使用流式或周期性 mini-batch k-means 更新原型；
- 比较新旧聚类分布；
- 仅当漂移超过阈值且新模型已经稳定时才进行切换。

有用的漂移信号包括质心移动、聚类占比的 Jensen-Shannon 散度、路由置信度、聚类的产生与消失，以及预测重用与实际重用之间差距的扩大。

## 5. 聚类分区缓存之外的替代设计

### 5.1 全局节点亲和度优化

完全避免逻辑分区。基于当前的 query 混合分布估计每个节点未来的期望命中次数，并在容量约束下保留全局最优的节点。聚类信息仅作为效用模型中的一个特征。这是最简洁的去重设计。

### 5.2 分层查询区域缓存

设置全局层、粗粒度聚类层和叶子聚类层。将节点分配到仍然具备可重用性的最高层级。这样可以自然地表示导航骨干节点、宽泛的语义区域和精细的局部邻域。

### 5.3 查询条件化的重用距离预测

训练一个轻量级模型，预测被扩展节点是否会在某个时间窗口内被再次使用。特征可以包括 query 到质心的距离、节点亲和度、跳数、度数、节点频率、当前重用距离和缓存压力。这是一种学习增强型替换策略，而不是固定启发式策略。

### 5.4 路径摘要缓存与预取

为每个查询区域学习一份高概率扩展节点或页面的紧凑摘要。在图遍历到达这些节点之前，使用该摘要提前准入或异步预取可能被访问的节点。评估预取时必须同时考虑有效预取率和额外 I/O，而不能只考虑延迟。

### 5.5 感知转移的区域预热

如果真实 query 流中存在稳定的聚类转移关系，则学习 `P(z_{t+1} | z_t)`，并保留或预热最可能成为下一个访问目标的区域。该设计利用了独立聚类热门程度之外的序列结构。

### 5.6 页面感知的亲和度缓存

按磁盘页面聚合 `A[v,z]`，并优化期望页面重用。即使没有任何单独节点在全局范围内被频繁访问，一个页面仍然可能具有较高价值。该设计使缓存策略与实际 SSD I/O 以及 Starling 风格的布局保持一致。

### 5.7 搜索阶段感知缓存

按照跳数或搜索阶段对扩展操作分类。早期导航节点更可能是全局节点，搜索后期的节点则更具有查询区域特异性。一种简单的“全局早期节点 + 聚类后期节点”策略，可能用更少的元数据捕捉 QASC 的大部分收益。

### 5.8 语义结果缓存

缓存最终结果集，并允许相近的 query 重用或细化这些结果。这在概念上与语义缓存或相似性缓存有关，但它会改变检索语义和 recall，因此应当与图节点缓存分开评估。

## 6. 推荐实现顺序

### 阶段 A：先测量，再编写策略代码

1. 在扩展 trace 中保留 query 边界和聚类 id。
2. 构建节点-聚类亲和度矩阵。
3. 测量节点亲和度熵、跨聚类重叠和每个聚类的未命中率曲线。
4. 量化相互独立的物理缓存会产生多少重复字节。

### 阶段 B：基线

1. 使用固定比例分区的硬聚类路由。
2. 带全局共享层的硬路由。
3. 使用单一去重存储的软 top-2 路由。
4. 对比 `n`、`sqrt(n)`、`n^0.75` 和注水式容量分配规则。

### 阶段 C：自适应策略

1. 衰减的节点-聚类亲和度。
2. 弹性配额与容量借用。
3. 漂移检测与周期性质心刷新。
4. 页面感知效用和可选预取。

## 7. 评估矩阵

始终报告：

- 数据集及其来源；
- query 顺序是原始顺序、随机打乱顺序、k-means 分组顺序还是真实时间顺序；
- query 聚类的数据来源和更新频率；
- 路由置信度和聚类占比；
- 以节点数和字节数表示的缓存容量；
- 全局层/条件层的容量划分；
- 避免的重复字节数；
- 命中率、平均 I/O、QPS、延迟百分位数和 Recall@10；
- 元数据内存开销和策略 CPU 开销；
- 冷启动/预热状态和线程数。

必须进行的消融实验：

- 每个聚类一个物理缓存，对比去重的共享存储；
- 无全局共享层，对比有全局共享层；
- 硬路由，对比软路由；
- 按比例分配容量，对比注水式容量分配；
- 离线原型，对比在线更新的原型；
- 节点感知效用，对比页面感知效用；
- 稳定负载，对比突发漂移和渐进漂移。

## 8. 相关研究及其与本问题的联系

- Dar et al., *Semantic Data Caching and Replacement*, VLDB 1996。该工作通过语义区域而不是对象标识来确定重用关系。这为按查询区域进行路由提供了依据，不过 QASC 缓存的是图节点而不是 query 答案。
- Garetto, Leonardi, and Neglia, *Similarity Caching: Theory and Algorithms*, arXiv:1912.03888。该工作对“相似对象可以满足同一请求”的缓存进行了形式化，直接有助于定义查询空间中的邻域和近似重用。
- Vietri et al., *LeCaR: Learning Cache Replacement with Regret Minimization*, HotStorage 2018。LeCaR 在最近性和频率两类专家策略之间进行学习，但其状态基于访问序列，并未以 query 几何关系为条件。
- Rodriguez et al., *CACHEUS: An Adaptive Cache Replacement Policy for a Changing World*, FAST 2021。CACHEUS 能够在多种时间局部性策略之间进行自适应；可以将查询区域加入为上下文特征或专家选择信号。
- Subramanya et al., *DiskANN: Fast Accurate Billion-point Nearest Neighbor Search on a Single Node*, NeurIPS 2019。DiskANN 的静态 BFS 缓存捕捉全局有用的导航节点，这对应于 QASC 的全局共享层。
- Chen et al., *SPANN: Highly-efficient Billion-scale Approximate Nearest Neighbor Search*, NeurIPS 2021, arXiv:2111.08566。SPANN 使用粗粒度区域和边界复制；其中的区域路由和重叠问题与 query 聚类缓存的路由问题类似。
- Wang et al., *Starling: An I/O-Efficient Disk-Resident Graph Index Framework for High-Dimensional Vector Similarity Search on Data Segment*, PACMMOD 2024, DOI 10.1145/3639269。Starling 表明，图布局和块 I/O 局部性必须与缓存一并考虑。
- Aumuller, Bernhardsson, and Faithfull, *ANN-Benchmarks*, Information Systems 2019, DOI 10.1016/j.is.2019.02.006。其数据集适合用于比较 ANN 的质量和速度，但大多数 query 顺序并不代表时间负载。

## 9. 当前建议

将简单的每聚类独立缓存实现为可证伪的基线，但主要设计应当面向去重的 Query-Affinity Shared Cache，并包含：

- 全局导航层；
- 软 query 路由；
- 衰减的节点-聚类亲和度；
- 弹性逻辑配额；
- 注水式容量分配；
- 在线漂移检测；
- 最终加入页面感知评分。

该设计与当前实验所观察到的真实因果结构保持一致：query 的几何关系决定搜索路径的重叠程度，而路径重叠又决定未来的节点重用。
